關鍵決策（2026-06）：
- 建構策略：垂直切片優先（非 design_docs §32 的 23 步水平建構）。
- **移植姊妹專案 `~/Documents/finflow_ai/apps/backend/app` 的「抓取/正規化/rate-limit 層」**（storage-agnostic，回 PriceRow/ChipRow dataclass）：`services/rate_limiter.py`、`twse.py`、`finmind.py`、`pcloud.py`、`storage_monitor.py`、`supabase_publish.py`、`retention.py`、`config.py` 模式。**複製檔案進 repo 改寫**（非 import），審查既有 bug、切斷對 finflow Postgres models 的相依避免耦合。

- 成本/容量上限走 env（`DAILY_COST_LIMIT_TWD`、`LOCAL_STORAGE_BUDGET_GB`）。
- 新聞分兩層：權威新聞可當 fact；PTT/Dcard 只當情緒訊號、強制標 inference 不可當事實。
