# Implementation Plan: 公司行動還原補完 + 行情完整性

**Spec**: [spec.md](./spec.md) | **Created**: 2026-10-13

## Summary

兩個獨立成因造成「還原後仍超出漲跌幅限制的單日跳動」，分別處理：

1. **漏掉的公司行動**（US1–US3）：`backend/processor/adj_factors.py`
   - 因子範圍檢查從固定的 (0.5, 1.0] 改成「範圍外者須經股價驗證」（`confirm_with_prices`）
   - 新增分割類、減資兩個來源；因子表以 `source` 欄區分，同日不同來源並存連乘
   - `repair()`：以異常跳動為線索做針對性補抓；`refresh_recent()` 每日補近 14 天
2. **行情缺日 / 錯置日 / 幽靈日**（US4）：`backend/data_sources/price_integrity.py`、`backfill_tw_market.py`
   - `_try(strict=True)`：回應日期須等於請求日
   - `backfill_dates()`：零散日期先收齊再一次寫入
   - `diagnose()` / `repair()`：以上櫃來源當交易日曆，找缺日、幽靈日；以普通股的跳動群聚找錯置日
   - `morning_brief._run_backtest_loop`：每日自癒近 45 天、一次最多 5 天

無新依賴、無 migration。既有 parquet 不重寫（spec 017 的 D2 不變），只增補事件與補回缺列。

## Constitution Check

- **IV 資料正確性**：本案即為此原則的修復。範圍外因子須經股價驗證、缺價不寫（fail-closed）。✅
- **II 成本紀律**：零 LLM 成本。資料源請求為針對性查詢，未全市場逐檔重掃。✅
- **V Local-First**：只動本機 parquet；補抓前已備份。✅
