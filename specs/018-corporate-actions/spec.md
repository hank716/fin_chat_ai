# Feature Specification: 公司行動還原補完（大比例配股、分割、減資）

**Feature Branch**: `chore/oct-review-batch`

**Created**: 2026-10-13

**Status**: Draft

**Input**: 2026-10-13 盤點時發現 spec 017 的還原因子表漏掉整類事件，使用者指示優先修復。

## 背景與問題

spec 017 以「除權息參考價比」還原股價，讓報酬、波動、均線與前瞻標籤跨除權息日連續。
當時為了擋掉壞資料，規定參考價比必須落在 0.5 到 1 之間，否則丟棄。

這個範圍對一般配息沒問題，但把三類真實事件全部擋在外面：

| 事件 | 參考價比 | 實例 |
|---|---|---|
| 大比例配股 | 遠小於 0.5 | 6669，2026-09-02，7,800 → 2,615（0.335） |
| 股票分割、面額變更 | 遠小於 0.5（反分割則大於 1） | 6949，2026-09-07，1,490 → 74.5（0.05） |
| 減資 | 大於 1 | 2380，2026-06-29，6.6 → 23.86（3.6） |

後兩類甚至不在原本查詢的資料來源裡。

**後果**：這些個股在事件日出現未還原的假漲跌。6669 在 9/02 的 -66.5% 讓它登上跌幅榜、
被 9/07 的晨報列入避雷名單，模型還得自己註明「受除權配股影響」。同樣的離群值也進了訓練特徵、
前瞻標籤與回測報酬——台股漲跌幅限制是 ±10%，任何超出的單日報酬都不該存在於還原後的資料裡。

**規模**（2026-10-13 掃描，4 碼普通股 1,984 檔）：還原後仍有 303 筆 / 222 檔單日漲跌超過 25%，
其中 203 筆成交額在 5,000 萬以上（會進候選池與主訓練池）。這 303 筆並非全是公司行動——
部分是行情資料本身有錯（例如 2026-03-18 多檔同時出現不合理低價）或無漲跌幅限制的交易日，
本案要把兩者分開。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 公司行動不再製造假漲跌 (Priority: P1)

發生大比例配股、分割、面額變更或減資的個股，其還原後的股價在事件日前後連續；
不會因為公司行動而登上漲跌幅排行、被列入候選名單，或在訓練資料裡留下超出漲跌幅限制的報酬。

**Why this priority**: 這是資料正確性問題（憲章 IV）。錯誤的報酬同時污染讀者看到的排行與
模型學到的型態，而且修之前做的任何準確度對照都帶著這層雜訊。

**Independent Test**: 取已知事件（6669、6949、2380），確認還原後事件日的單日報酬落在漲跌幅限制內，
且事件前的歷史報酬不受影響。

**Acceptance Scenarios**:

1. **Given** 6669 於 2026-09-02 大比例配股，**When** 讀取還原價，**Then** 當日報酬約 -0.2% 而非 -66.5%。
2. **Given** 6949 於 2026-09-07 面額變更，**When** 讀取還原價，**Then** 事件前後股價連續。
3. **Given** 2380 於 2026-06-29 減資恢復買賣，**When** 讀取還原價，**Then** 當日不出現 +225% 的假漲幅。
4. **Given** 顯示給讀者的價格與觸價判定，**When** 還原規則變更，**Then** 仍使用原始名目價（spec 017 的 D2 不變）。

---

### User Story 2 - 壞資料不會被當成公司行動套用 (Priority: P1)

放寬範圍後，來源若給出錯誤的參考價，不得讓一檔個股的整段歷史被錯誤的倍率改寫。

**Why this priority**: 原本的範圍限制存在是有理由的。拿掉它而不補上別的防線，等於把
「漏掉真事件」換成「套用假事件」，後者更糟——它會改寫整段歷史而不是只影響一天。

**Independent Test**: 構造一筆參考價比 0.3 但實際股價沒有對應跳動的事件，確認不被採用。

**Acceptance Scenarios**:

1. **Given** 一筆範圍外的事件，其參考價比與事件日實際股價變動相符，**When** 處理，**Then** 採用。
2. **Given** 一筆範圍外的事件，實際股價沒有對應變動，**When** 處理，**Then** 丟棄並留下紀錄。
3. **Given** 一筆範圍外的事件，事件日行情尚未入庫，**When** 處理，**Then** 暫不採用，待行情到位後再驗。

---

### User Story 3 - 剩下解釋不了的跳動有清單可查 (Priority: P2)

補完後仍超出漲跌幅限制的單日跳動，會被列成清單（哪一檔、哪一天、幅度），
讓人能判斷是行情資料錯誤、無漲跌幅限制的交易日，還是另一種尚未涵蓋的事件。

**Why this priority**: 303 筆裡有一部分不是公司行動。不列出來，就無法知道修復的涵蓋率，
也無從處理剩下的資料品質問題。

**Independent Test**: 執行補抓後檢視清單，筆數應明顯少於 303，且可逐筆對照行情。

**Acceptance Scenarios**:

1. **Given** 補抓完成，**When** 檢視結果，**Then** 可得「補抓前筆數、寫入事件數、剩餘筆數」與剩餘清單。

---

### User Story 4 - 行情缺日與錯置日被找出並補回 (Priority: P1)

*2026-10-13 補抓後追加。* 修完公司行動後，4 碼普通股的異常跳動只從 303 筆降到 254 筆。
剩下的經對照上游確認，是行情列本身的問題：

- **缺日**：66 個交易日完全沒有上市個股的列（只有上櫃），包含 2026-10-08、09-24 這樣的近期日。
  單日抓取失敗時回空、回補游標照樣前進；每日刷新只回看近幾天，漏掉的就永遠是洞。
- **錯置日**：交易所偶發回應的日期與請求不符，別天的行情被標成另一天落地並覆蓋正確資料
  （3189 在 2026-03-18 存的是 03-04 的行情 284.5，實際收盤 365.5）。
- **幽靈日**：錯置日期落在週末或假日時，產生不存在的交易日（5 天，各約一千檔）。

三者都讓「跨多日的報酬」被當成「單日報酬」，污染所有以天數計算的特徵與前瞻標籤，
影響面比公司行動更廣——每個缺日波及全部約一千檔上市股。

**Why this priority**: 不補這一塊，User Story 1 修掉的只是異常的一小部分，
修復後的評估對照也沒有意義。

**Independent Test**: 補抓後重新統計每日上市列數，缺日應歸零；3189 在 2026-03-18 的收盤應為 365.5。

**Acceptance Scenarios**:

1. **Given** 某交易日沒有上市個股的列，**When** 例行巡檢，**Then** 該日被重抓補齊。
2. **Given** 交易所回應的日期與請求日不同，**When** 寫入，**Then** 整批丟棄，不以回應日期落地。
3. **Given** 資料中存在非交易日的列，**When** 巡檢，**Then** 這些列被移除。
4. **Given** 近 45 天內出現新的缺日，**When** 每日例行維護，**Then** 自動補上，不需人工介入。

### Edge Cases

- 同一天同時發生除息與減資：兩者都要還原，不得互相覆蓋。
- 事件後停牌數日才恢復買賣：以恢復買賣當日與停牌前最後一日比對。
- 上市首幾日無漲跌幅限制：不是公司行動，不應被補抓誤判，也不應因此反覆查詢。
- 小幅減資（參考價比 1.0–1.25）：單日變動與一般漲跌難以區分，偵測不到（已知限制）。
- 來源額度用盡：停手並保留進度，下一輪續跑，不得寫入半套結果。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 還原大比例配股、股票分割、反分割、面額變更與減資，使還原後股價在事件日前後連續。
- **FR-002**: 參考價比落在一般配息範圍（0.5–1）之外的事件，MUST 經實際股價驗證後才採用：
  參考價比須與「事件日開盤 ÷ 前一交易日收盤」相符。
- **FR-003**: 驗證不過、或事件日行情尚未取得的範圍外事件 MUST NOT 被採用；丟棄須留下可查的紀錄。
- **FR-004**: 一般配息範圍內的事件處理方式 MUST 維持不變。
- **FR-005**: 同一檔同一天的不同類事件 MUST 並存並連乘還原。
- **FR-006**: 系統 MUST 能找出還原後仍超出漲跌幅限制的單日跳動，並只針對這些個股補查事件來源，
  不得為此全市場逐檔重查（來源有每小時額度，且與歷史行情慢爬共用）。
- **FR-007**: 補查後仍無法解釋的跳動 MUST 落地成清單供稽核。
- **FR-008**: 新發生的事件 MUST 在每日例行維護中被補上，不需人工介入。
- **FR-011**: 行情寫入 MUST 以請求日與回應日一致為前提；不一致的回應 MUST 整批丟棄。
- **FR-012**: 系統 MUST 能找出沒有上市個股資料的交易日、不存在的交易日、以及多檔同時出現
  異常跳動的可疑日，並重抓或移除。
- **FR-013**: 近期缺日 MUST 在每日例行維護中自動補回。
- **FR-009**: 顯示價與觸價判定 MUST 繼續使用原始名目價。
- **FR-010**: 修復前後 MUST 以同一資料截止日各跑一次評估快照並對照（全域決策 D1）。
  這是正確性修復，不設「指標必須變好」的門檻。

### Key Entities

- **還原事件**：一檔個股在某一天的參考價比，附事件來源類別（除權息 / 分割類 / 減資）。
- **未解釋跳動**：還原後仍超出漲跌幅限制的單日變動，含個股、日期、幅度。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 6669（2026-09-02）、6949（2026-09-07）、2380（2026-06-29）三個已知事件還原後，
  事件日單日報酬的絕對值皆低於 12%。
- **SC-002**: 還原後超過 25% 的單日跳動筆數較修復前（303 筆）明顯下降，剩餘者全數列於清單。
- **SC-003**: 構造的錯誤事件（參考價比與股價不符）採用數為 0。
- **SC-004**: 修復前後同截止日的評估快照對照表產出並記錄。
- **SC-006**: 補抓後，沒有上市個股資料的交易日數為 0，非交易日的列數為 0。
- **SC-007**: 4 碼普通股還原後超過 25% 的單日跳動筆數降到 60 筆以下，且剩餘者不再有日期群聚。
- **SC-005**: 補抓使用的來源請求數不超過「有異常跳動的個股數 + 1」。

## Assumptions

- 事件來源沿用既有資料供應商：除權息結果（逐檔）、分割與面額變更（可全市場一次取得）、
  減資參考價（免費層僅能逐檔）。
- 以 25% 作為「超出漲跌幅限制」的偵測門檻，留空間給無漲跌幅限制的正常交易日。
- 行情資料本身的錯誤原本列為範圍外；補抓後發現它才是異常的主體，已納入 User Story 4。
- 上櫃個股的行情走另一個逐檔來源，沒有錯置日問題，可作為判斷「哪些天是真的交易日」的依據。
- 股利事件特徵（spec 020）只計一般配息，分割、減資與大比例配股不計入殖利率。
